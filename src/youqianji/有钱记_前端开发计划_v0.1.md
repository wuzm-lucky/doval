# 有钱记前端开发计划

| 项目 | 内容 |
|---|---|
| 文档版本 | V0.1 |
| 日期 | 2026-09-05 |
| 前端项目 | `doval`（Vue 3 + Vite + TDesign Next） |
| 适用目录 | `src/youqianji/` |
| 后端基线 | 《有钱记开发计划 V0.2》《有钱记数据库详细设计 V0.1》 |

## 1. 目标与边界

本计划用于将有钱记 V1 后端开发阶段映射为可独立验收的前端页面、路由、接口联调和测试任务。前端以 API First 为原则：页面仅消费后端正式接口契约，不自行推导账户余额、资金归属、快照估值或账务规则。

前端需要帮助用户准确理解“钱在哪里、属于谁、发生了什么变化、当前与历史价值如何变化”。复杂证券、基金、港股打新等交易规则不在 V1 页面中实现；复杂账户仅展示快照资产、资金轨迹和账户内部价值变化。

## 2. 实施原则

- 所有有钱记页面、路由、状态、接口封装和通用组件放在 `src/youqianji/` 范围内，避免侵入既有业务模块。
- 沿用 `doval` 现有 Vue 3、Vite、TDesign Next、路由、请求封装、权限和多语言约定；实现前先复用现有通用能力，不重复造轮子。
- 金额展示必须使用后端返回的原币金额、币种和估值质量。前端不得使用 JavaScript 浮点运算重算余额、汇率或净资产。
- 账户详情可见性、家庭报表策略和页面操作权限完全以服务端返回的权限结果为准；前端仅负责隐藏无权限入口和友好提示，不作为权限边界。
- `LEDGER` 与 `SNAPSHOT` 账户在页面中必须有明确模式标识。Snapshot 账户显示“快照时间、是否待同步、Bridge 临时影响”，不能把资金轨迹当作直接余额变化。
- 所有会造成资金事实变化的提交操作必须提供二次确认、幂等防重复提交、成功后刷新事实数据；已记账流水仅提供查看、冲正入口，不提供直接编辑或删除。

## 3. 前端模块规划

```text
src/youqianji/
├── api/                 # 有钱记接口模块，按领域拆分
├── constants/           # 页面枚举、展示映射和固定文案
├── hooks/               # 家庭上下文、金额展示、权限判断等复用逻辑
├── router/              # 有钱记路由定义或路由注册入口
├── stores/              # 当前家庭、页面筛选条件等前端状态
├── types/               # API DTO/VO 的 TypeScript 类型
├── utils/               # 金额格式化、币种与估值质量展示工具
├── views/
│   ├── family/          # 家庭切换、成员、主体与设置
│   ├── account/         # 平台、账户树、账户详情、授权
│   ├── transaction/     # 流水列表、详情、收入支出转账换汇录入
│   ├── snapshot/        # 快照录入、快照版本、汇率
│   ├── receivable-payable/
│   ├── plan/
│   └── report/
└── components/          # 账户选择、金额输入、归属拆分、流水分录等领域组件
```

实际目录、状态管理和请求封装必须以 `doval` 既有工程规范为准；若现有结构不同，保持概念分层一致即可。

## 4. 路由与菜单

建议路由前缀统一为 `/youqianji`，最终路径和菜单注册方式以 `doval` 现有路由机制为准。

| 路由范围 | 页面 | 优先级 | 对应后端能力 |
|---|---|---:|---|
| `/youqianji/overview` | 资产概览 | P1 | 家庭资产、净资产、待办和资产趋势。 |
| `/youqianji/family` | 家庭切换与设置 | P0 | 家庭、成员、主体、基础币种和时区。 |
| `/youqianji/account` | 账户列表与账户树 | P0 | 平台、账户、层级、可见性和报表策略。 |
| `/youqianji/account/:id` | 账户详情 | P0 | 原币余额、归属、流水、快照与历史值。 |
| `/youqianji/transaction` | 流水列表 | P0 | 分页、筛选、详情、冲正。 |
| `/youqianji/transaction/create` | 新增资金变更 | P0 | 收入、支出、转账、换汇、退款、调整。 |
| `/youqianji/snapshot` | 快照与汇率 | P0 | 快照录入、版本、汇率维护与估值质量。 |
| `/youqianji/receivable-payable` | 应收应付 | P1 | 借贷、结算、逾期与明细。 |
| `/youqianji/plan` | 收支计划 | P1 | 模板、实例、匹配和完成状态。 |
| `/youqianji/report` | 基础报表 | P1 | 资产、收支、归属、应收应付和趋势。 |

## 5. 分阶段开发计划

### M1：家庭、主体与账户（P0）

1. 接入有钱记菜单、路由守卫和当前家庭上下文。
2. 实现家庭切换、家庭设置、成员和主体管理页面。
3. 实现平台管理、账户列表/树、账户新建编辑、账户状态与账户授权页面。
4. 在账户卡片、树节点和详情中明确展示：资产/负债、流水/快照、可见性、家庭报表策略、账户状态。
5. 建立账户选择器、主体选择器、币种金额展示等复用组件。

验收：不同家庭数据切换不串扰；私有账户不可通过路由跳转或前端缓存查看；账户树可区分父账户自身余额与子账户归集值。

### M2：核心记账与流水（P0）

1. 实现流水列表、筛选、详情和冲正入口。
2. 实现收入、支出、同币种转账、跨币种换汇、退款、调整和期初余额的录入向导。
3. 按交易类型动态展示账户、分类、交易对手、手续费、汇率、资金归属和业务归属字段。
4. 实现多主体资金归属选择：来源归属唯一时自动带入；归属存在歧义时强制用户明确选择或选择待分配。
5. 明确显示流水状态：草稿可编辑/删除，已记账只读且可冲正，已冲正关联原流水和冲正流水。

验收：前端不自行计算借贷平衡；提交后以服务端返回结果刷新列表、余额和详情；重复点击不会造成重复提交。

### M3：快照、Bridge 与估值（P0）

1. 实现 Snapshot 账户快照录入、快照列表、版本关系、作废/替代提示和历史查询页面。
2. 实现快照多币种余额和每个币种的资金归属录入；归属差额必须清晰提示为待分配。
3. 实现汇率录入、导入结果展示和汇率质量标识。
4. 在 Snapshot 账户详情中展示最近快照、快照生效时间、Bridge 净流入/流出、快照待同步状态和账户内部价值变化。
5. 估值缺失或使用历史近似汇率时，显示明确质量提示，不以精确金额样式误导用户。

验收：Bridge 仅作为临时资产影响展示，不被渲染为普通账户余额流水；历史快照补录或更正后可刷新相应历史视图。

### M4：应收应付与计划（P1）

1. 实现应收应付列表、详情、创建、收款/还款和多笔结算匹配页面。
2. 显示本金、利息、费用、已结算、剩余、到期日期与状态。
3. 实现计划模板、计划实例、实际流水匹配和逾期状态页面。
4. 对部分完成的计划实例展示剩余金额及所属周期，不把未完成金额错误滚入下一期。

### M5：概览、报表与集成反馈（P1）

1. 实现家庭资产概览：家庭净资产、管理资产、资产/负债分布、待收待付和快照待同步提示。
2. 实现资产、净资产、收支、归属、应收应付及资产趋势报表。
3. 支持家庭、主体、平台、账户、币种、时间和资产归属组合筛选。
4. 对 `SUMMARY_ONLY` 账户只展示允许的汇总金额，不泄露账户名称、流水、分类或私人主体信息。
5. 为外部同步的快照和资金流展示来源、同步时间和幂等处理结果；不在前端展示内部密钥或敏感来源信息。

### M6：质量与交付

1. 完成 P0/P1 页面回归、权限回归、移动窄屏适配和空状态/加载/异常状态检查。
2. 校验金额、币种、日期、时区、估值质量和敏感账户展示的一致性。
3. 清理调试代码、无效路由、废弃接口调用和重复组件。
4. 更新页面说明、接口联调记录与开发日志，完成发布前验收。

## 6. 接口联调顺序

前端不得等待所有后端完成后再统一接入。每个阶段以稳定的 OpenAPI/Swagger 契约为准，先完成页面骨架、空状态和类型定义，再接入正式接口。

| 阶段 | 前端接口模块 | 联调完成条件 |
|---|---|---|
| M1 | family、subject、platform、account、category | 家庭切换、账户树、账户权限与分类接口可端到端使用。 |
| M2 | transaction、ownership | 已记账流水、冲正、余额和归属以服务端响应为准。 |
| M3 | snapshot、exchange-rate、valuation | 快照版本、Bridge 提示、估值质量和历史查询可联调。 |
| M4 | receivable-payable、plan | 结算、计划匹配、部分完成与逾期状态一致。 |
| M5 | report、integration | 汇总与明细权限一致，报表数值可与后端样例核对。 |

接口类型需集中维护，禁止页面内散落硬编码 URL、字段名和枚举展示文案。新增或调整接口后，应同步更新类型、模拟数据和对应页面验证。

## 7. 领域组件与交互要求

| 组件 | 用途 | 核心要求 |
|---|---|---|
| 账户选择器 | 选择资金账户 | 显示资产/负债、模式、币种与可用状态；不可选择无权限或已归档账户。 |
| 金额输入 | 原币和换汇金额 | 按币种精度限制输入；不使用浮点数展示或计算。 |
| 归属分配器 | 资金归属拆分 | 显示待分配差额；多归属转出不能默认按比例分摊。 |
| 业务归属选择器 | 收支主体 | 与资金归属分开，收入/支出默认带入账户默认主体。 |
| 流水分录预览 | 提交前确认 | 只展示后端定义的业务含义和金额，不在前端生成账务分录。 |
| 估值质量标识 | 汇率/估值提示 | 区分精确、人工、交叉推导、历史近似，缺失时明确提示。 |
| 快照版本提示 | 快照纠正与来源 | 显示生效时间、版本、来源和是否被替代。 |

## 8. 前端测试与验收

### 8.1 必测场景

| 场景 | 验收重点 |
|---|---|
| 家庭切换 | 页面状态、筛选条件和缓存均按家庭隔离。 |
| 私有账户 | 无权限用户无法从菜单、搜索、路由或缓存看到明细。 |
| 同币种转账 | 页面显示为资金转移，不作为收入或支出展示。 |
| 换汇 | 原币、目标币、手续费、交易汇率和估值提示清晰分离。 |
| 多归属转出 | 必须选择归属或待分配，不默认比例扣减。 |
| 已记账流水 | 禁止编辑删除，只允许查看或按权限冲正。 |
| Snapshot Bridge | 显示临时资产影响与待同步提醒，不伪装成正式快照余额。 |
| 汇率近似 | 历史近似汇率必须有视觉提示。 |
| 报表隐私 | `SUMMARY_ONLY` 不泄露账户明细、分类和私人主体信息。 |
| 历史补录 | 刷新后历史日期的流水、资产和趋势视图正确更新。 |

### 8.2 质量要求

- 沿用 `doval` 已有的 lint、类型检查、构建和测试命令；每个阶段提交前执行相应检查。
- 关键资金录入操作至少覆盖组件或页面级自动化测试；权限、错误提示与重复提交必须有回归场景。
- 接口不可用、估值缺失、空账户、无快照、无权限等场景必须提供明确空态或错误态。
- 页面不得把后端的内部错误信息、授权令牌、请求头或来源密钥展示给用户。

有钱记前端开发日志统一记录在 `src/youqianji/有钱记_前端开发日志.md`。首次实施 M1 时创建；每个可独立验证的批次完成后必须追加记录。

```markdown
## YYYY-MM-DD｜M<阶段>｜前端｜<批次名称>

- 计划目标：
- 已完成：
- 修改范围：
```

## 10. 交付门禁

| 阶段 | 前端完成门禁 |
|---|---|
| M1 → M2 | 家庭隔离、账户权限、账户树和 P0 账户页面通过联调。 |
| M2 → M3 | 收入、支出、转账、换汇、退款、调整的录入与已记账只读规则通过回归。 |
| M3 → M4 | Snapshot、Bridge、估值质量、快照版本和历史刷新展示正确。 |
| M4 → M5 | 应收应付与计划的部分完成、逾期、匹配和冲正后的展示一致。 |
| M5 → M6 | 报表汇总、隐私策略、加载异常状态和关键窄屏页面通过验收。 |
| M6 完成 | 前端检查、构建、核心页面回归、日志和联调记录完整。 |

后续预算、资金目标、账单导入和扩展交易模块均以本计划的目录隔离、服务端事实优先、权限分层和日志记录规则为基础继续迭代。
